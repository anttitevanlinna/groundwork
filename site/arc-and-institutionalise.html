Reading your own arc

A word is defined by its citations, not by how you remember using it — and the loop only closes when the lesson ships: narrated from the files, pruned to what still fires.

A lexicographer never defines a word from how they remember using it — they read the dated slips where it was caught in the wild, written by people with no stake in the meaning. After a stretch of real work, your arc is the word and your artefacts are the slips: the ./CLAUDE.local.md that grew rule by rule, the ADRs, the skills, the RUN-NOTES.md. So don't write the definition. Hand the slips to a reader who was never in the room, make it read the arc back, then cut the rules the read proves stale.

The reading · do this Monday

Hand the slips to a reader who was never in the room — then cut one rule the read proves stale.

  1. Open a fresh Claude Code session in the repo where your last real arc of work lives — an agent with no memory of it, so it can't keep your wins and quietly edit the dead ends. Hand it a bounded read-list, named files, not the whole history: the root rules file, ./CLAUDE.local.md, the memory folder, any ADRs, every skill in ~/.claude/skills/ you authored there, the last run's RUN-NOTES.md. Each was written in the moment with no incentive to look good later — which is exactly what makes it the honest record.
  2. Ask for one page, in the instruction that does the work: write from my artefacts, quote me where you can, skip the summary of what the training taught. Require it to quote your own files back — if it can't point to the line a claim came from, it narrated from your chair. Re-run with quote-required.
  3. Reject any line that reads like a trainer monologue — "this journey taught me to embrace…" The slips don't talk like that. If a stranger could mistake the page for marketing copy, the voice slipped; send it back to the files.
  4. Read the page against your own memory and mark where the evidence disagrees with your story. Then, while you're in the rules file, find one rule the arc just made stale — superseded, or no longer matching how you work — and delete it in place, the deletion visible in git. A file that only grows is one nobody re-reads; the arc-read is where you earn the right to shrink the kit.
  5. Ship the page where the next session reads first — an ADR, an observations/ memo, or a file you'll point an agent at. Not a diary entry: the cold-start brief for whoever inherits the repo, teammate or future-you. The loop closes when the lesson ships.

This is the hinge between "I learned this" and "the org keeps it." An evidence-narrated arc is the strongest opener for the team conversation — you arrive with the arc, not an opinion — and it's how a company-scale context layer stays legible and lean enough to be re-read rather than skimmed. A learning system whose state lives only in one person's head has a learning rate that resets to zero the day they leave the repo.
