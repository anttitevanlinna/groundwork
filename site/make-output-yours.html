Recipe · R1 · the first move on any agent file

Make output yours

The principle: Context is King — a cleverer prompt won't save you; structured context will.

Steer the agent with structured context until the output sounds like a real person or company, not the LLM — by changing what the agent sees, not how cleverly you ask.

The agent isn't generic. Your context is — the guardrail is the only thing that changed.
The mechanism · how the sausage is made

Same words, different answer.

The most useful thing to understand about a coding agent is also the most unglamorous: it isn't looking your question up in a database. Every turn, it re-reads the whole conversation and generates the next response from all of it. Your first prompt and its answer are now part of the input to the second prompt. Change the front, change the back. That's it. That's the lever everything else in this operating model — tools, goals, checks, boundaries, loops — sits on top of. None of them work unless the agent reads the right world first.

The cleanest demonstration takes ninety seconds. Open three fresh windows. In each one, ask "What should we have for dinner?" as the second turn — but vary the first. Window A's first turn is "What is the capital of Italy?" / "Rome." Window B's first turn is "What is the largest lake in Finland?" / "Saimaa." Window C's first turn is "I'm a cardiologist preparing dinner for my patients." Same exact follow-up. Three answers that drift Italian, Finnish, and heart-healthy respectively. The context that colours output isn't only nationality. It can be a fact, a role, a preference, a constraint — anything you tell the agent. Window C's answer shifts not because Claude suddenly knows medicine better than it knows Italian cooking, but because you told it who you are and every answer after took that into account. The mechanism is dumb and total: whatever you put in front, you'll find pulled through to the back. Garbage in, garbage back. Specifics in, specifics back. The shape of what you give it is the shape of what you get.

A cleverer prompt won't manufacture facts you never gave it. Only structured context can.

The shelf-life upgrade · from chat to file

From the fading message to the file the agent reads cold.

What we just did was an ephemeral message — typed into a chat, gone when the window closes. Powerful per session, useless next Monday. The move that survives the weekend is the same mechanism with a different shelf life: turn that context into a file the agent reads at the start of every conversation. CLAUDE.md in a Claude Code project. A rules file the agent loads cold. Same physics — the agent reads it as part of the input — but now the steering is durable, version-controlled, and starts the next session sharper than the last one ended. Below: chat-bubble fading on the left; rule file glowing on the right.

Process diagram · 02Guardrails are structured context, not a checklist. A file the agent reads cold makes the next session start sharper than the last one ended.

The compounding step is where most teams under-invest, and where the gap with serious operators widens fastest. The first version of any rule file is never exactly right. Two paragraphs are too thin; ten paragraphs are noise the agent skims past. You only find out which two were the load-bearing ones by using the file again, noticing what the agent still got wrong, and editing. Same move you used here on a one-pager, you'll use on every agent file from now on — module 1 lands the muscle; later modules systematise it.

The compounding loop · what changes between passes

The rule file gets sharper every time you put it to work.

The picture below shows the four-beat loop with the file itself getting visibly denser between passes. Notice the order: you do the work first — you don't sit and write rules in the abstract. Reflection without a real run produces opinions, not guardrails. Then you capture what mattered. Then you reflect. Then you sharpen the file. Then you do the next piece of work, which is the first run against the sharper file, which is also the first place you discover what's still missing. Compound interest on a rule file. Boring on day one; dominant by day thirty.

What "Test" actually means · in practice

The test that matters is "yes, that's it."

The test that matters is "yes, that's it" from someone who knows the subject cold — not "that's polished" from a stranger, and not "looks good" from Claude itself. Polish-praise rounds corners. Asked to comment on a stranger's bio you'd reach for "reads well, nice tone." Asked about your own bio, the wrong adjectives jump off the page like a typo. Domain expertise is the eval. When you read the output, push back on anything that doesn't match your own gut; that's the pattern. Every time you do the work and reflect, the rule file gets sharper, and the next pass needs less pushing-back to land. This is also why module 1 of Agents 101 puts you on a one-pager about yourself — you cannot fool yourself on your own material, which is exactly the calibration you need to spot fabrication everywhere else later.
