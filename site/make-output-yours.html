Making output yours

We noticed AI made assumptions and mistakes. Then we realised that was most often because AI just did not have the right rules to follow. It way back then actually had no rules. No context. Every chat started from zero.

The principle: Context is King — a cleverer prompt is a cleaner rinse; it never puts colour in cloth that never met dye.

The model's flat, generic answer isn't a flaw to prompt your way around — it's undyed cloth, sitting in the mean of everything it ever read. Steer it with structured context, then a rules file it reads cold, until the output comes out the shade of a real person or company. Change what you feed it, not how cleverly you ask.

The undyed cloth is the model in the mean. The dye-bath is the only thing you changed.

The grey is a default, not a fate.

Every consultancy crossing your threshold sells the same fix for grey, not-quite-yours output: a cleverer prompt. A better incantation, a prompt-engineering course, the phrasing that finally makes the model sound like you. It is the wrong drawer entirely. Picture the model as undyed cloth — it comes out of every bath the colour of the mean of everything it ever read, and asking more cleverly doesn't change that. What changes the colour is what you drop in before you ask. That is the one sentence of metaphor you need; the rest is just how an agent actually reads.

Here is the unglamorous mechanic underneath. A coding agent isn't looking your question up in a database. Every turn, it re-reads the whole context window — the system prompt, any loaded files, the entire conversation so far — and generates the next response from all of it. Your first exchange is now part of the input to the second. So a prompt can't retrieve facts the window never held; it can only re-comb what is already steeped in there. Same words in, whatever the window holds comes back out.

A cleverer prompt is a cleaner rinse. It cannot put colour in cloth that never met dye.

Sometimes I feel like painting with a virtual text brush. I'm forcing myself to apply the brush rather than typing a single character at a time. I feel like I'm trying to set the state of the LLM right. Then I ask it to paint as I need. It is kind of like oil painting.

“Toward Integration” · Aug 2025 · unpublished

You can prove it in ninety seconds, no org data required. Open three fresh windows. In each, ask "What should we have for dinner?" as the second turn — the identical follow-up, the exact same words — but vary the first exchange, the thing the window steeps in before you ask. Window A steeps in "What is the capital of Italy?" / "Rome." Window B in "What is the largest lake in Finland?" / "Saimaa." Window C in "I'm a cardiologist preparing dinner for my patients." The follow-up never moves. The answer comes out Italian, Finnish, heart-healthy. The context decided the shade.

The dye-bath demoSame prompt to the agent, three contexts, three answers. Whatever the window steeped in is the dye — the answer comes out the colour of what you fed it.

What dyes the window isn't only nationality — it can be a fact, a role, a preference, a constraint, anything you steep it in. Window C shifts not because the model suddenly knows medicine better than Italian cooking, but because you told it who you are before you asked. That works, and it also bleeds out the moment you close the tab: the typed-in turn lives only inside that one window's context. Powerful this session, gone by Monday — a dye dropped in plain water.

The mordant goes in before the dye.

A dyer fixes colour with a mordant — a fixative added before the dye so the colour both takes and lasts, never a better rinse after. The agent's mordant is a file it loads cold at the start of every conversation: CLAUDE.md in a Claude Code project, alongside the memory and source files an agent reads before it does anything. Same physics as the chat turn — it lands in the context window — but now the steering is durable, version-controlled, and the next session starts the shade the last one ended. You stop re-typing who you are. The fixative sits in the project, going in first, every run.

The first dyeing is never the right shade — two rules are too thin to hold, ten are noise the agent skims past. You only learn which took by running the cloth through the wash again: do the work→capture→reflect→sharpen, in that order. Reflecting before a real run produces opinions, not guardrails. Fastness, not brilliance, is what compounds — boring on day one, dominant by day thirty.

These files and folders become the context where you can unleash the Ai. Ai is generative but without context and intent it ends up outputting generalities. Or if you ask Ai to ideate freely, then you still need to context to evaluate what is good and what is bad.

“Time to rethink your knowledge management” · Sep 2025
The dyer's eye

The test that matters is "yes, that's it."

It comes from someone who knows the true shade cold — not "that's polished" from a stranger, and not "looks good" from the model that mixed it. Polish-praise rounds the corners: asked about a swatch you've never made, you reach for "reads well, nice tone." Asked about your own swatch, the wrong shade jumps off the cloth like a typo. Domain expertise is the eval. When you read the output, push back on every line that doesn't match your gut — that's the pattern, and each wash needs less pushing-back to land. This is why module 1 of Agents 101 puts you on a one-pager about yourself: you are the one dyer you cannot fool on your own swatch — exactly the calibration you'll need to catch a faked colour everywhere else, where you can't see it coming.

Dye your first swatch tonight.

Start on the one shade you can't be fooled on — something you know cold.
  1. Ask vanilla Claude Code to write a one-pager about you, sourced from your own LinkedIn. Read the grey baseline. That's the undyed cloth.
  2. Drop in the mordant: who it's actually for, the two or three facts no model could guess, your real voice. Re-run.
  3. Where you're the expert, mark every flattened line — and every fabricated one — the way a wrong shade jumps off a swatch.
  4. Write the rules that fixed it into a CLAUDE.md the next session reads cold. Run it again; watch the colour hold.
~45 min · vanilla Claude Code · your own LinkedIn · no org data. The first hour of Agents 101 — and the move you'll reuse on every agent file after.

You are the one dyer you cannot fool on your own swatch.

Flat output becomes genuinely yours not because you rinsed harder, but because the mordant is the control. A cleverer prompt can't put colour in cloth that never met dye; only structured context — fed into the window before you ask, then fixed in a file the agent reads cold — can. The move is structural, not stylistic. And spotting a faked colour on something you know cold is the foundation everything later in the operating model rests on: verification, evals, judges, autonomy. Skip this and the rest is theatre.

The same physics holds at company scope. The agents your whole team runs come out the colour of the shared files behind them — the house-style file, the memory, the sources you commit once are the mordant the next hundred runs steep in. You're putting the dye in the bath for everyone downstream.

The model isn't grey. Your context is the dye.
