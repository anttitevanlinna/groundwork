The contrarian read · what's actually expensive

You banked the decision. You lost the loaded context that made it obvious.

A threat-model pass flags one thing worth hardening. You weigh the trade-off, pick a side, ship the fix, and move on with the small relief of being past it. That relief is the trap. The intuition says the choosing was the hard part — but choosing is cheap. The expensive thing was loading the context that made one option obviously right: the attacker you were picturing, the alternative you rejected and why, the single constraint that broke the tie. That context decays fast and silently, and a feeling of having decided is not an artefact. A week later someone in review asks "why this and not the obvious alternative?" and you reconstruct a rationale you no longer actually hold — or defend a guess.

In an agentic workflow the decay costs twice. The agent that picks up adjacent work next week has no memory of the room where you decided. It reads the repo cold, sees a settled trade-off with no recorded reason, and does the rational thing — re-litigates the call from scratch, sometimes landing back on the option you already rejected, for the exact reason you already rejected it. The load-bearing line · what ages well

The verdict is in the diff. The constraint is the only thing that expires.

Here's the part the intuition gets backwards. The expensive thing to preserve isn't what you decided — anyone can read the diff and see you chose option X. The expensive thing is the constraint that made X obvious at the time. That single line is the test by which a future reader knows whether your call still holds when the inputs change. "We scoped the token to read-only because the endpoint is reachable unauthenticated" ages gracefully — the day the endpoint goes behind auth, anyone can see the call is now reversible. Strip the constraint and all that survives is a verdict with no expiry date, defended forever by reflex because nobody remembers what would falsify it.

A decision you can't reconstruct isn't a decision you still own — it's a guess you'll re-make under worse conditions.

The move, then, is not "document more." It's a shelf-life upgrade on a single decision: take the rationale that currently lives as a fading thought and turn it into a numbered file the repo carries forward. The convention most teams reach for is an Architecture Decision Record — a short, standalone, repo-resident note, one per decision, numbered so they read as a history. Not a wiki page that rots in a corner, not a Slack thread that scrolls away, not a commit message buried in history. A file the next session — yours or an agent's — cold-reads as part of the system's standing context. Four lines do the work:

the logbook entry — four lines, one decision
  1. Context. the threat you were picturing — e.g. an unauth read endpoint a STRIDE pass surfaced.
  2. Decision. the call you actually shipped — scope the token to read-only.
  3. Alternatives. what you weighed and dropped — gateway allow-list, per-call auth.
  4. The constraint that picked the winner. reachable unauthenticated — so least-privilege. This is the bearing. It's the one line that ages.

Default shape, not a mandate. The path docs/adr/NNNN-slug.md and the four sections are an illustrative default — if your repo already has an ADR convention, use theirs. The portable part is the discipline, not the directory name.

What thickens · the org stops storing reasoning in heads

One record is a note. A directory of them is the layer the next call rests on.

One ADR is a note. A repo of them is a different thing entirely — the layer the next decision rests on instead of fighting against. Each pass thickens the docs/adr/ directory, and each new constraint is read as standing context by whatever reads the repo next: a reviewer, a junior who wasn't in the room, a memory pass that loads prior decisions, or an agent doing adjacent work. Decision-recall stops depending on the person who made the call still being available — or still remembering. That's the systemic win: an org's architectural reasoning starts living in the codebase, not in senior heads. The one trap to refuse — treat the ADR as a checkbox after a menu-pick threat and you get paperwork: a fabricated trade-off written to satisfy a form. A genuine trade-off written down is design; a fabricated one is theatre. Write only what you actually decided.

So the move this week is small and immediate: after your next real trade-off, stop for ninety seconds while the why is still warm and log four lines into docs/adr/NNNN-slug.md (or wherever your repo keeps them) — context, the call, the alternative you rejected, and the constraint that decided it. You're not proposing a process or asking anyone's permission; an ADR is a markdown file in a directory you already own, and you're writing down a decision you already made. Do it once and the why stops evaporating; do it after every real call and the directory becomes the substrate every future reader — human or agent — inherits instead of reconstructs.
