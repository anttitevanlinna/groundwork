Splitting work across agents

You cannot add many documents into a single session. You cannot build universal agents. Even the agent definitions of some of our more ambitious assistants need splitting into multiple context windows and sessions. When the context window is “full” or over, then the agent goes braindead.

You keep hiring three of the same agent — then act surprised the committee agrees with itself.

Adding a second agent is a hire, and the screening question is the one any honest hiring manager asks: does it reach somewhere the first can't, read a source the first doesn't, or hold a position the first won't? If not, you have one prompt in three costumes. When the difference is real, the move is to make the agents disagree on disk and force a framework to pick — not let a chat smooth the friction away. SCOPE · personal → team → company: a single builder's split becomes the org's standing way of staffing a question.

One prompt in three blazers — or three agents, three context files, one judge. The filesystem is the meeting room.

You almost ran it: staff this question with three agents, because three minds beat one and the org chart looks serious. Here is what the impressive shape won't tell you. You keep filling three seats with the same agent — same sources read, same dialect spoken, same opinion held — and then you're surprised the committee agrees with itself. A second agent that reaches what the first reaches, talks how the first talks, and leans the way the first leans is not a colleague. It's a prompt you photocopied twice and paid to run three times. So before you split anything, run the interview.

Round oneThe screen — name the forcing axis or close the req

Three agents, or one prompt in three costumes?

Hold the three candidates side by side and ask the only screening question that matters: does any of them reach a source the others can't, read it in a language the others don't, or argue a position the others won't? Three agents pointed at the same context window, retrieving the same documents, reasoning in the same register and landing the same conclusion are not three agents. They are one prompt that owns three costumes — and they will outvote your doubts three-to-nothing, because they were never built to disagree.

So name the difference out loud, on exactly one axis. Access: they literally reach different things — one is scoped to the internal wiki, one to the data warehouse, one to the open web. Dialect: the sources don't speak the same language and shouldn't be flattened into one before you've read them apart. Stance: the question needs a planner, a skeptic, and a reframer arguing, not one agent averaging the three in a single pass. If you can't put your finger on which axis is making one agent impossible, you don't have a panel — you have one prompt cosplaying as three, and the coordination cost is pure waste.

Can't name the axis? Close the req. You just kept the coordination cost in your pocket and lost nothing.

Round twoDon't let them rehearse the same answer — separate sessions, separate files

Give each agent its own source zone and forbid the green room.

Once the difference is real, the worst move is to run all three in one thread and let them reconcile as they go. Sizing a market is the canonical case, because the answer is genuinely three answers in three dialects: the loud answer — press releases, analyst forecasts, the figures everyone repeats; the academic answer — benchmarks, papers, the careful caveated version; and the quiet answer — practitioner blogs, repo activity, what people say once the slides are off. Give each its own session scoped to one source zone, and forbid them to compare notes before they write.

Where they write is the point: not a chat, but the disk. The filesystem is the meeting room. One file per source zone — loud.md · academic.md · quiet.md — non-comparable on purpose. A chat thread is built to reconcile; it quietly resolves the conflict on the way through, and the disagreement you split to find dies there. A file just records what its agent saw, and lets the contradiction sit on disk long enough for a judge to read it. Nothing needs procuring first: several sessions on one working directory already run, so you open two more in the folder you're already in.

Three files, three dialects, no green room. The seam you'd have lost in conversation is now sitting on disk.

Round threeThe panel, not one tired interviewer — distinct stances under a rubric

A judge that argues beats one agent averaging three files.

Synthesis is not one tired agent reading three files and quietly splitting the difference. Point a judge at the three files and give it distinct stances to hold — a planner, a what-would-have-to-be-true skeptic, and a reframer (that trio is the default starting line-up, not the only correct one — swap a seat if your question fits a different argument). Then bind the judge to a rubric that forces one question before it writes a sentence of synthesis: where do these three contradict each other?

Drop the rubric and the judge does what any model does at a fork — it rounds the corner and makes peace. Hand three conflicting files to an un-briefed synthesiser and you get a fluent, reasonable, utterly beige consensus, the very thing you opened three sessions to avoid. The rubric is the judge's spine: show me where these disagree, before you write a word. Without it you have built an expensive route back to the single-agent answer.

A briefed judge picks a direction; an un-briefed one hedges. The rubric is what makes it choose.

Round fourThe reference you keep — and the one you can run on Monday

Write down which seat earned its desk, then start there.

After the answer lands, don't bin the interview notes. In the review, write down which session actually earned its keep and which was the photocopy you should have screened out — into the root ./CLAUDE.md that governs how the next question gets staffed: this zone was noise, that stance was redundant, the rubric needed a sharper "show me the seam." That one sharpening clause is the whole compounding mechanism — the first time you split a question you're guessing at the division of work; by the third you're not, because the next split starts from earned rules a teammate inheriting the folder reads from too.

So here is Monday, and it's smaller than the diagram. Take one question you keep getting beige back on from a single agent. Write down which one of access, dialect, or stance is forcing the split — if you genuinely can't name one, stop, keep the single agent, and pocket the coordination cost. If you can name it, open two sessions on the same folder, point each at a different source zone, and make each write its own file before anything synthesises. Two sessions · two files · no third agent yet · no rubric yet. Then read the two files side by side and notice the seam you would have lost in a single chat.

By the third question you're not guessing at the org chart — you're staffing it against rules that earned their lines.

The exit test

You passed only if a colleague reading the synthesis can see where the three disagreed — and the answer is specific enough to act on with its gaps left plainly visible.

That's a harsher bar than "looks thorough." The seam has to show, because the judge picked a direction instead of hedging the three into a mush. And then the test most candidates-for-splitting fail, which is the entire point: if one good prompt would have produced the same answer, you didn't run a panel — you paid three salaries for one opinion. Most questions live on that side of the line. The discipline is learning the move and respecting the default.

Close the req. Keep the single agent. That is a pass too.
