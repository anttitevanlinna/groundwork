The fixed-judge loop

If you don’t have evals, then you cannot let Ai loose to iterate autonomously toward the goal. You are all the time babysitting and nudging. But now that you have your evals and iteration, you let LLM run.

The principle: a yardstick you rewrite is not a yardstick — freeze the standard and let the work chase it.

Treat the standard like the platinum cylinder that was the kilogram — one object held still on purpose, never edited — then put the rest down and work in real agent terms. You write your quality bar into one judge.md, point a separate generator agent at it, and feed every correction the judge returns into a tactic file — never the judge. One file moves round after round; one never does. That's how a standard stops being one desk you sit at and becomes a file a whole team's agents can run against, unattended.

One agent loop, three rounds. tactic.md chases; judge.md holds.
The mechanism · which file is allowed to move

Pin the standard; let the work chase it.

Start with the inversion, because it's the whole pattern. In make output yours you steer a fresh agent by changing the input — you edit the prompt, the CLAUDE.md, the sources in context, until the output drifts to follow. Here you run it backwards: you pin the standard so the output can't hide behind a moving target, and let the generation chase it. The standard lives in one file — call it judge.md — and you declare it untouchable for the run. The generator's how-to lives in a second file, tactic.md, and that one is allowed to thicken. One file moves; one does not.

Lose that discipline and you measure nothing. The seductive failure feels like diligence: you set out to improve a recurring output, so each round you sharpen the work — and, while you're in there, you sharpen judge.md too. A tighter criterion here, a kinder threshold there. Round three scores higher than round one and you congratulate yourself. But the work and the yardstick both moved, so the number is hollow: you cannot tell whether the work got better or the bar got softer. A score is only comparable when the thing producing it stays fixed. Freeze the judge, and round three's number finally has something honest to say about round one.

Process diagram · 01The inverse of steering. Here the standard is pinned and the work moves toward it — a later round is comparable to an earlier one only because the judge held still.

One structural rule makes the whole thing honest: the agent that writes the work and the agent that grades it must be different. Run them as two separate sessions, with two separate prompts — the generator reads tactic.md and writes a draft; the grader reads judge.md and the draft, and returns flags. A single agent grading its own output drifts, slowly and plausibly, toward flattering itself — not from malice, but because inside one context the cheapest way to score higher is to soften what counts as good. The asymmetry is the design: one part writes and wants to pass, one part rejects and owes nothing. Nothing marks its own homework.

Freezing the judge looks like giving up control. It's the opposite: it's your taste, delegated and made durable.

Your ceiling is how well you can capture the elusive “truth”.

The upgrade · from reading every draft to designing the loop

You stop reviewing outputs. You start designing the loop.

The reason this matters to you is brutally practical. Today the recurring check — the weekly board narrative, the customer release blurb, the renewal-risk read — runs because you run it. You are the bottleneck and the quality bar at once, and the day you're on a plane the bar travels with you. Lift your standard out of your head into judge.md, and a generator agent can chase it while you do something else entirely. The restraint to leave that one file alone is the entire price of admission — and it's the move from operator to owner.

Make the investment proactively. Put in the sensing with and for the customers. Then you can have Ai search for an optimal solution. Evals is the sensing.

One lap, logged

Not a recipe — a single run, in order. Pick one recurring output you currently sanity-check yourself — the weekly board note, the customer release blurb. Then watch which file is allowed to move.

00:00 · write
Write the standard that output must meet into a one-page judge.md — the criteria you'd apply by hand. Then make one promise: I do not touch this file again this run. Save it. From here it's the cylinder under glass.
00:04 · split
Open two separate agent sessions — one writes the draft against tactic.md, one grades it against the frozen judge.md. Nothing marks its own homework; the separation is the whole integrity of the lap.
00:10 · round one
Generate the draft. The grader returns its flags. Feed every flag into tactic.md — and never back into the judge. The judge absorbs nothing; the tactic absorbs everything and visibly thickens.
00:22 · round two
Re-run the draft with the thicker tactic, grade it against the byte-identical judge. If round two beats round one against a judge that did not move, you've felt the loop — not believed in it, felt it.
00:30 · carry
Three markdown files, two sessions, about thirty minutes. You keep the round-by-round trail — the score, what the judge kept catching — so you walk into the make-this-a-team-check conversation holding a score trail, not a pitch.
Refuse the kind advice

The fast-iteration playbook will tell you to co-evolve: sharpen the work and sharpen the rubric together each round, "as your taste develops." Refuse it. A standard you are allowed to amend mid-run is not a standard — it is a mood. The moment judge.md is editable by the same hand that wants the score to go up, the grade is worthless: you have co-authored the verdict with the defendant.

And do not soften the rule when a round disappoints and the obvious fix is to relax one criterion. Ask the loop instead: "which rule did you claim to remove but actually kept under another name? Quote both lines." If generation could secretly edit the judge, that question has nowhere honest to land. If your "improvement" came from loosening the judge, you didn't tighten the work — you moved the goalposts.

A yardstick you rewrite is not a yardstick. The standard does not get a vote on its own grade.

Where this sits · personal → team → company

A fixed judge is the verification primitive a company's autonomy rests on. Alone it raises one person off the bottleneck; shared, it lets a team run the same standard unattended; and once your taste lives in a frozen judge.md that separate agents are scored against, quality stops being a person reviewing every output and becomes infrastructure the whole company can trust agent work against — one standard, not one desk at a time. That trust is the precondition everything above it composes on. It's the same shape the software lane calls verifier-shaped-to-failure: freeze the check, evolve the code — different surface, identical move.
