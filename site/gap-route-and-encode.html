Route each gap to its home

The principle: the loop closes when the lesson ships — but only to the home where it'll fire.

Take the gaps a two-run compare handed you and send each one to the right home — memory, a sharper verifier, or a new skill — instead of pouring all of them into a skill because skills feel like the answer. The home you pick decides whether the lesson ever fires when you need it. It's a private fifteen-minute pass, but it's also the dispatcher a company-scale context layer either institutionalises or drowns under: prevention in memory, detection in CI, reuse in skills — or one undifferentiated pile.

The funnel is the trap. Three gaps want three homes — and one of them is a rule you delete.
The mechanism · how the lesson finds its home

A rule, a check, and a skill are three different times.

You ran the same task twice — once un-packaged, once packaged — and the contrast handed you a fistful of things the run didn't anticipate: a rule the agent never had, a check that would have fired mid-run if it existed, a move you keep re-explaining every session. The trap the source curriculum names outright is what happens next. You pour all of them into a new skill, because a skill feels like the satisfying artefact to ship. But a rule isn't a skill, and a missing check isn't a rule. The three homes the source sorts gaps into — memory, a sharper verifier, a new skill — are not a tidiness exercise. They are three different times a lesson can act: a rule acts before the run, a verifier acts during it, a skill acts on the next run of this shape.

So the routing question is really a timing question. Ask each gap one thing and the answer falls out. Would a rule have prevented this before the run started? — then its home is memory; the agent should have had the habit from cold start. Would a check firing while the run was still going have caught it? — then it wants a sharper verifier, because rules prevent, they don't catch. Will I re-perform this exact move on the next task of this shape? — then, and only then, it earns a skill. Route a lesson to the wrong time and it never fires when you need it. The framing is load-bearing, so be precise about it. Memory holds what prevents, a verifier holds what detects, a skill holds what you'll reuse — the source curriculum's three-way sort, drawn from a convergent practitioner pattern read off the encode end of Armin Ronacher's reference / plan.md / verifier trio, with the prevent / detect / reuse timing as this card's gloss on why it works. One honest caveat: it's the source's sort, not an official Claude Code taxonomy or a measured law — useful, well-worn, and open to a fourth home. What is observed: lessons filed in the wrong place stop firing.

A rule that prevents a mistake upstream does more, cheaper work than a skill that re-catches it every run.

The upgrade move · from skill-funnel collapse to routed map

Stop pouring. Sort, then file.

The comfortable collapse is to make everything a skill — it feels productive, and it fires nothing, because most of what you learned wasn't a reusable move. The upgrade is two beats. First, hold the gaps as a list before routing any of them — three, maybe four, dominant first; don't reach for the fix on the first gap. The source caps this deliberately: pick the three that cost the most. Over-routing is its own failure; a long catalogue produces noise, not a loop. Then tag each gap with the prevent / catch / reuse question and actually file it in its home — including the one move that struck through, because deleting a stale rule is routing too. The diagram below walks the diagonal.

Process diagram · 02The comfortable collapse fires nothing. Routing is what turns a gap list into a loop — file each gap where it acts, the cut included.

Why does subtraction count as routing? Because an instrument calibrates by removing as much as by adding. The two-run contrast often shows a rule in ./CLAUDE.local.md that didn't fire, didn't help, or no longer matches how you work — we use Mongo when you switched to Postgres months ago. A gap can be negative: the absence the loop wants is a rule removed, not added. Delete it in place, with the deletion visible in git history. The source calls this compound-by-subtraction, and names the opposite as a failure mode — addition-only compounding, where a student only ever adds rules and never cuts one. A rules file that only grows is a file that's stopped being read honestly.

The compounding loop · leaner and fuller each pass

Each lap the file is both fuller and leaner.

Notice the rules file across passes: hash marks added, some struck out, and the gaps getting quieter each lap. This is the named principle doing its work — the loop closes when the lesson ships, to the home where it fires. Ship it to the wrong time and the lap doesn't close; the same gap surfaces again next run, wearing a different hat.

Test · how you know the routing worked

Each gap has exactly one named home, and you can say in one sentence why that home and not the other two — "this is memory because a rule would've prevented it, not a check that would've caught it." If a gap resists the question, it's doing two jobs; split it.

At least one gap routed to memory as a deletion — git history shows a rule cut, not only rules added. Pure accretion means you skipped subtraction. And not everything became a skill: if all your gaps ended up in one new SKILL.md, you collapsed the routing — re-sort.

The skill you did author moves to catch its gap: its description ends with an outcome, not a topic. If it reads like a documentation page describing the gap, it's mis-routed — that gap was probably a rule. (Skill-as-documentation is the source's named diagnostic, a practitioner teaching observation about why loops stall — not a measured rate.)

Use when

You've diagnosed two runs of the same task, you hold a fistful of gaps — and your instinct is to pour all of them into a new skill, because skills feel like the answer. Recurs at every loop closure: after a two-run compare, after a CI red the loop should've caught.

A routed gap map — a short ranked list (M6 scrollback, optionally durable in observations/) where each gap is tagged with its home and actually filed there, one stale rule cut in place.

Why
The principle

The loop closes when the lesson ships — but only to the home where it'll act.

"A rule, a check, and a skill are three different times a lesson can fire — route it to the wrong time and it never fires at all."

The counterintuitive part: the satisfying artefact is the wrong default. A skill is the heaviest of the three homes — a move you'll re-invoke — so it feels like the serious place to put a lesson, which is precisely why undisciplined engineers route everything there. But a rule that prevents a mistake upstream does more, cheaper work than a skill that re-catches it every run; and a check that fires mid-run protects you in ways no rule can.

The three homes aren't a tidiness exercise — they're three different times a lesson can act: a rule before the run, a verifier during it, a skill on the next run of this shape. Route a lesson to the wrong time and it never fires when you need it. The deletion arm matters for the same reason — an instrument calibrates by subtraction as much as addition, and a rules file that only grows is a file that's stopped being read honestly. (The three homes are the source's three-way sort — a convergent practitioner pattern, not an official Claude Code taxonomy — and stay open to a fourth home.)
