The access surface

The principle: Map what you're protecting before you name what could go wrong.

A fire marshal counts every door out of a building before anyone games the break-in — so send a fresh subagent to walk the feature and chart every way in, while you keep your attention for the two doors only you can name: the one it drew too thin, and the one it never drew. Breadth is borrowed; judgment is yours.

Every door charted by the subagent. The two amber ones are yours — and STRIDE waits outside until the plan is whole.
The move that fails "Ship it, bolt the auth on later." Run the whole thing through STRIDE, then patch wherever it flinches. Both threat-model a vibe — six categories floating over a surface nobody actually charted.

Map a feature's access surface and you find most of the labour isn't yours. The entry points, the trust boundaries, the data tiers, the auth checkpoints — that's a long, structured breadth read, and a breadth read is exactly what you hand to a fresh subagent. Invoke a curated access-control skill, name the feature by route or a couple of symbols, and let it find the code itself — it burns its whole context window walking the tree, so yours stays clean for the part it can't do. What stays with you is two doors only you can name: the one it drew too thin, under-weighted against what you know this codebase actually does, and the one it never drew at all — the entrance that lives in your head and nowhere in the obvious code.

Make the read cover six surfaces, not five: entry points · trust boundaries crossed · data and its sensitivity tier · auth checkpoints, split into present, assumed, and delegated · external connector calls · and the load-bearing one — anything that bypasses, defers, or inherits an auth decision made elsewhere. That last door is where the surprises live. A generic reader handles standard middleware well and hand-rolled, inherited-elsewhere auth worst of all — which is precisely where breaches breed. A good skill doesn't fake omniscience; it narrates what it misses while it works — flags that a parent router's middleware propagates downward, flags bespoke auth it reads worse than the standard kind — then closes with a calibrated self-grade and names where the last percents hide. A flagged uncertainty beats a confident fabrication; those flags aren't noise to skim, they're invitations addressed to you.

The skill reads the standard doors well and the weird ones badly. The weird ones are where the break-ins happen.

The governing readSame feature, two readers. Breadth from the skill, depth from you — they converge on the delta note, and that join is the only thing STRIDE gets to read.

Now the door you can't delegate. Read the map's confessed blind spots — don't skim them — and write the delta: two surfaces, each reasoned in this codebase's own terms. One the skill flagged harder than you would have. One you know matters that it missed. Push every reason until it names something a different codebase wouldn't share. "This export route trusts the tenant id in the path, not the session" beats "check the auth." The first is yours; the second is anyone's. And the delta — not the skill's wall of output — is what STRIDE reads next. The raw map is the input to your judgment; the delta is the artifact. Each feature you map this way widens the kit the next feature's read starts from: the surface you name once, hardened into a team ADR, becomes default breadth the skill carries on its own — so the discipline compounds across features rather than resetting each time.

This week, the feature you're closest to shipping. Name it in one sentence, ask Claude Code to run the access-control skill on it as a subagent — no file paths — then write two lines: one door it flagged harder than you would have, one it missed that you know matters. The skill reads the tree; you write the delta, before your next PR review. You know it worked when both lines are present and neither is generic — and when the skill caught at least one thing you'd have missed.

Where it sits

This is the first guardrail in the trust arc: paired with STRIDE and the ADR under pressure, it walks a single engineer into staff-engineer and CISO review with a defensible map, a hardening decision, and a named residual risk. And that same chart-the-doors-before-the-build discipline is what scope-for-trust raises to company scope — the precondition for an org trusting an agent it didn't personally calibrate. Map a feature's access surface here; scope an agent's surface to what the org can trust there — same move, two surfaces.
